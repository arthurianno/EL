## Как работает buildType:
Система автоматически определяет buildType из gradle task:
- `./gradlew assembleDebug` → buildType = "debug"
- `./gradlew assembleRelease` → buildType = "release"  
- `./gradlew assembleHuawei` → buildType = "huawei"

## Один раз (сейчас):
```bash
git tag -a v2.10.5.395-release -m "Current release 2.10.5"
git push origin v2.10.5.395-release
```

## Каждый релиз:
```bash
# 1. Отредактировать version.properties (build + 1)
nano version.properties

# 2. Закоммитить
git add version.properties && git commit -m "Bump to 396" && git push

# 3. Создать тег
git tag -a v2.10.5.396-release -m "Release 396" && git push origin v2.10.5.396-release

# 4. Собрать
./gradlew assembleRelease     # Google Play
# или
./gradlew assembleHuawei      # Huawei AppGallery
```

## Формат тега:
```
v{major}.{minor}.{patch}.{build}-{type}
```
Где `type` = `release`, `debug`, или `huawei`

## Примеры:
```bash
v2.10.5.395-release    ✅
v2.10.5.396-huawei     ✅
v2.11.0.397-release    ✅
```

## Как работает система:
1. Есть Git тег на коммите? → Используется версия из тега
2. Нет тега? → Читается version.properties
3. Нет файла? → Hardcoded fallback (v2.10.5.395-release)
