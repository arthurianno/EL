# Предложения обновления через Firebase Remote Config

Приложение использует существующее окно «Обновить / Позже». Установка выполняется
в магазине. SDK обновлений и изменения API сервера не требуются.

## Начальная настройка

В проекте Firebase `elta-31f0d` откройте Remote Config. Добавляйте новые параметры
через **Add parameter**, не заменяя существующие `recovery_account` и
`improved_enabling_location`, их значения и условия.

| Parameter name | Data type | Default value |
| --- | --- | --- |
| `app_updates_enabled` | Boolean | `false` |
| `android_google_latest_version_code` | Number | `0` |
| `android_google_update_url` | String | `https://play.google.com/store/apps/details?id=com.elta.android` |
| `android_rustore_latest_version_code` | Number | `0` |
| `android_rustore_update_url` | String | `https://www.rustore.ru/catalog/app/com.elta.android` |

Сохраните параметры и опубликуйте конфигурацию с `app_updates_enabled=false`.
Это подготовка настроек: предложение обновления остаётся выключенным.

## После публикации нового релиза

1. Убедитесь в консоли магазина, что новая сборка доступна пользователям.
2. Для соответствующего магазина установите **versionCode**, например `420`.
   Это не строка версии `2.10.9`.
3. Включите `app_updates_enabled=true` и опубликуйте конфигурацию.
4. Для второго магазина оставьте `0`, пока релиз в нём не опубликован,
   или укажите номер его реально доступной сборки.

При поэтапном выпуске дождитесь доступности релиза для всех целевых пользователей
перед общим включением предложения: без SDK приложение не проверяет индивидуальную
доступность обновления в магазине.

## Поведение приложения

- Сравнивается установленный versionCode с опубликованным номером сборки.
- Для установки из Google Play проверяется Google Play; для RuStore — RuStore.
- Если источник установки неизвестен, доступны только магазины с более новой
  опубликованной сборкой и корректной ссылкой на это приложение.
- При нескольких доступных магазинах кнопка «Обновить» предлагает выбор.
- Если приложение магазина недоступно, открывается та же страница в браузере.
- Предложение откладывается до завершения синхронизации и готовности приложения.
- Без интернета оно не показывается. Ошибка получения конфигурации не блокирует работу.
- Повторное предложение возможно через три дня после фактического показа окна,
  включая закрытие кнопкой «Позже», жестом или кнопкой «Назад».
- В релизной сборке Firebase кеширует полученную конфигурацию до одного часа.
  После изменения параметров предложение не обязательно появится немедленно.
- Обязательное обновление по ответу сервера `MANDATORY` сохраняется.
  Для Google Play и RuStore обычные предложения управляются Firebase,
  а прежний серверный статус `OPTIONAL` не создаёт второе окно.
- Сборки Huawei сохраняют существующий серверный сценарий обновлений.

## Отключение

Установите `app_updates_enabled=false` и опубликуйте конфигурацию.
Это отключит новые предложения после получения приложением настроек;
уже открытое окно автоматически не закрывается.

## Локальный предпросмотр

В отладочной сборке окно можно открыть без изменения Firebase:

```sh
adb shell am start -W -n com.elta.android/.presentation.features.app.ui.AppActivity --ez debug_preview_app_update true
```

Это макет с двумя магазинами. Кнопка обновления показывает выбор; выбор магазина
показывает сообщение предпросмотра и не запускает переход или установку.
Предпросмотр не записывает трёхдневный таймер. В релизной сборке этот запуск отключён.

Новая логика требует выпуска приложения с этим кодом. Ранее собранный релиз 419
новые параметры не использует. Его тег и AAB сохраняются отдельно.
