# Исходный аудит нового auth-дизайна — 15.10.2026

Этот документ описывает состояние **до исправлений**. Выполненные изменения и результаты повторной проверки: [auth-fix-2026-10-15.md](auth-fix-2026-10-15.md).

Результат: **полного совпадения с актуальным макетом нет**. Проверка выполнена на текущем Android-коде, без изменения production UI. Предыдущие изменения PIN не затронуты.

## Источники и границы проверки

- Получен актуальный high-fidelity design context и screenshot [экрана входа Figma `788:5009`](https://www.figma.com/design/WArRV2xcji2Ns1kWwtFQo8/?node-id=788-5009). Он отличается от старой локальной metadata-выгрузки: заголовочный блок теперь начинается по X=16, кнопка имеет X=16/W=343.
- Следующие запросы восстановления/нового пароля/страницы Figma ответили: `You've reached the Figma MCP tool call limit on the Starter plan`. Актуальные макеты этих экранов, регистрации, активации и приветствия полностью не получены. Для них можно подтвердить текущую геометрию/доступность, но не точное соответствие Figma.
- [Предыдущее исследование](auth-recovery/README.md) — историческая частичная спецификация. Его X=27 и CTA X=32 не имеют приоритета над новым design context входа. Не переносить автоматически старые измерения на все экраны.
- Выполнен рендер Compose UI в instrumented ComponentActivity: 375×812/fontScale1.0 и 320×640/fontScale1.5, с настоящей клавиатурой эмулятора Android10. Это проверка компонентов и shared layout, не всех маршрутов production Activity/Dagger/backend.
- Состояния: вход, регистрация, активация, восстановление, новый пароль, приветствие; ошибки четырёх форм; клавиатура четырёх форм. Данные локальные тестовые, remote screenConfig не загружался. Отдельно проверяется доступ к CTA прокруткой.

### Верхний отступ: существенная оговорка

В baseline-эмуляторе верх title Text оказался Y=100 — как и в Figma. Однако Android status inset=30, toolbar=48 и spacer=22; Figma status=44, toolbar=44 и gap=12. Одинаковое абсолютное Y получилось при разных системных областях. Нельзя говорить «верх совпал на всех телефонах» и нельзя исправлять это жёстким Y=100. Сверять нужно отступ от toolbar и реальные line/baseline metrics с native insets.

Рендер входа: title X27/Y100/H29; description X27/Y137/H45. Figma: title X16/Y100/line27, description X16/Y136/H40. В локальной строке description также есть принудительный `\n` перед «и пароль…», ограничивающий адаптацию переносов.

### Иллюстрация входа

Оригинальный PNG Figma получен по asset URL из design context. Его размер1077×1460; slot375×360, image width95.06%, height134.49%, X9.5%, Y−2.64%. Локальный `img_login.png` — уже скомпонованный export1500×1440. При сравнении на белом фоне с преобразованием Figma среднее абсолютное отличие по RGB <0.36 из255 на канал. Это подтверждает практически эквивалентную картинку/кроп с учётом округления и ресемплинга; причина основных расхождений — layout/text, а не другая иллюстрация.

## Остальные экраны и доступность

1. **Регистрация + клавиатура:** на375×812 кнопка «Продолжить» изначально не видна. Минимальная иллюстрация, заголовок, поля и длинный consent превышают viewport. Проверено: прокруткой CTA достигается и отображается. Для макета с постоянно видимой CTA нужна другая компоновка: отдельно закреплённое действие и прокручиваемый контент, с учётом реальной доступной высоты.
2. **Компактный экран + fontScale1.5:** заголовки/описания занимают несколько строк; при focus автоматическая прокрутка может увести часть title выше видимой области. Footer/actions не гарантированно видны одновременно с полями. Это не доказательство перекрытия клавиатурой: нужно различать scroll и обрезание.
3. **Восстановление:** CTA имеет обычный horizontal padding27; вход/регистрация/новый пароль —32. Информационная строка: gap после email24, gap icon→text11. Историческая выгрузка показывает соответственно32/16/10; актуальное значение надо подтвердить свежим макетом, а не объявлять историческую таблицу истиной.
4. **Новый пароль:** расстояние helper→CTA12, а историческая геометрия показывает16. Верх/межстрочные интервалы наследуются от shared auth layout. Актуальный дизайн не получен.
5. **Активация:** используется реальная локальная картинка ноутбука. Комментарий в source о замене на original Figma export ещё есть; по одному TODO нельзя утверждать, что текущая картинка неправильная. Происхождение/точный кроп требуют сверки с актуальным узлом.
6. **Greeting:** собственный layout: top40 и side27/20, другой фон/привязка иллюстрации. Не менять его автоматически вместе с AuthScreenLayout: у него отдельный макет, актуальный узел не получен.

## Что подтверждено положительно

- Gotham32 и Roboto17 для главной иерархии входа используются; baseline переносы читаемы.
- Кнопки соответствуют H52/radius10 для обычного текста; disabled surface `#E3E3E3`.
- Иллюстрация входа практически совпадает с оригинальным Figma-asset/crop.
- Общий layout измеряет heading/form, уменьшает иллюстрацию и допускает scroll вместо наложения блоков.
- 7 модульных тестов AuthLayoutMetrics прошли, включая короткие viewport, ошибки, ширины и крупный текст. Это не тесты совпадения с Figma.
- Визуальный capture-run успешно прошёл в двух конфигурациях:28 исходных снимков и8 scrolled-снимков, плюс geometry JSON для обоих режимов. На375×812 CTA изначально видна у входа/восстановления/нового пароля, не видна у регистрации; на320×640/fontScale1.5 изначально не видна у всех четырёх форм. Все8 CTA со включённой клавиатурой доступны прокруткой, `performScrollTo().assertIsDisplayed()` прошёл.
